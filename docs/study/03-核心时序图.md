# 核心时序图（W0 产出）

> 用 mermaid 画，把类名/表名补全。面试讲项目时的骨架就是这三张图。

## 时序 1：后台登录 + JWT 鉴权（mall-admin / mall-security）

```mermaid
sequenceDiagram
    participant C as 前端
    participant S as Security 过滤器链
    participant U as UmsAdminService
    participant R as Redis
    participant J as JwtTokenUtil
    C->>S: POST /admin/login (username,password)
    S->>U: loadUserByUsername
    U-->>S: UserDetails + 权限
    S->>J: generateToken
    S->>R: 写入 token / 权限缓存
    S-->>C: {tokenHead, token}
    Note over C,S: 后续请求带 Authorization: Bearer xxx
    C->>S: GET /admin/info (Bearer)
    S->>J: parseToken / 校验签名
    S->>R: 查 token 是否存在（是否被登出）
    S->>S: DynamicAuthorizationManager 校验 URL 权限
    S-->>C: 数据
```

> 必答：JWT 无状态，怎么实现"登出"和"改密后旧 token 失效"？

## 时序 2：下单主流程（mall-portal / OmsPortalOrderServiceImpl）

```mermaid
sequenceDiagram
    participant C as 前端
    participant O as OmsPortalOrderServiceImpl
    participant DB as MySQL
    participant MQ as RabbitMQ
    C->>O: POST /order/generateOrder
    O->>DB: 校验库存（hasStock）
    O->>DB: 锁定库存（lockStock：查-改-写）
    O->>DB: 插入 oms_order / oms_order_item
    O->>DB: 清空购物车
    O->>MQ: 发送延迟消息（订单超时取消）
    O-->>C: 订单信息
    Note over MQ: TTL 到期 → 死信 → CancelOrderReceiver 取消订单并释放库存
```

> 必答：`lockStock` 的并发问题是什么？延迟队列和定时扫表各自的优缺点？

## 时序 3：商品搜索（mall-search / EsProductServiceImpl）

```mermaid
sequenceDiagram
    participant C as 前端
    participant E as EsProductController
    participant S as EsProductServiceImpl
    participant ES as Elasticsearch
    participant DB as MySQL
    C->>E: GET /esProduct/search?keyword=
    E->>S: search(keyword, page)
    S->>ES: 查询（multi_match / filter / sort）
    ES-->>S: 命中商品 ID 列表
    S->>DB: 按 ID 回查商品详情（或直接返回 ES 文档）
    S-->>C: 分页结果
```

> 必答：ES 和 MySQL 数据怎么同步？为什么搜索用 ES 不用 MySQL like？
